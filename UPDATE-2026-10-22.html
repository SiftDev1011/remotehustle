Additional update: international phone numbers

Sign-up and programme registration now include 245 country/territory dialling options, including Botswana (+267), India (+91), Nigeria (+234), the UK (+44), the US and Canada (+1). Choose the phone’s country and enter the local number, or paste a full international number. The phone country is independent of country of residence. Phone numbers are normalised on the server before saving, including country-specific trunk prefixes.

Additional installation step: after migration 014, apply supabase/migrations/202610220015_international_phone_numbers.sql. If 014 is already applied, run only 015. This extends the existing database phone constraint to accommodate shorter international numbers while preserving stored numbers and uniqueness. Run npm ci to install the pinned numbering-plan dependency, then restart or redeploy.

The additional checks passed: 92 automated tests, TypeScript and the production build. Browser tests covered both forms, +91 pasted numbers, +267 local numbers, prefilled international numbers, invalid-number feedback, the canonical server payload and widths from 320 to 1440px. These interaction checks used local service fixtures and did not send real sign-up emails. The dependency audit reported no known vulnerabilities at the time of this update.

International payment options

Recommended for this release: keep the existing Paystack integration and request international payments. Paystack supports international cards for approved businesses. In the live business dashboard, open Settings → Preferences, check whether international payments are enabled, and request access if needed. Complete business activation and any requested verification first.

The current app sells in NGN. With Paystack’s international-card approval, the customer’s bank can convert the NGN charge from the card’s currency. Accepting an international card is different from displaying prices in multiple currencies. USD pricing and settlement would require both provider enablement and changes to the app’s pricing, orders, verification and payment-correction paths; changing a single currency setting is insufficient.

Flutterwave is a possible alternative for a Nigerian business and supports international cards and additional regional payment methods. Available methods depend on the merchant account, currency and region. A switch would need a new payment adapter, webhook authentication and processing, transaction verification, retries and reconciliation tests, plus approved merchant credentials.

This package retains Paystack. No new gateway account has been created or enabled and no payment provider has been switched.

Sources checked 22 October 2026: Paystack international payment activation and currencies; Flutterwave payment methods.

1. Install the update

  1. Back up your current source and database. Extract this ZIP into a separate folder and merge the changes into your working repository. Keep your own .env.local and Vercel environment variables; no credentials are included in this ZIP.
  2. If migrations 001–013 are already applied, run only supabase/migrations/202610220014_programme_registration.sql in your Supabase SQL Editor. If this is a fresh database, apply all SQL files in filename order. Do not rerun older creation migrations on an existing database.
  3. Install the locked dependencies and validate:
npm ci
npm run typecheck
npm test
npm run build

Restart your local server with npm run dev. Commit the source and lockfile to your company repository and redeploy Vercel after the migration succeeds. No new environment variables are needed for these features.

The migration adds two public tables with row-level security, a private attempt counter and permission-checked database functions. It also updates the admin attention function and the policy version recorded for future sign-ups. Existing registrations, approvals and consent records are preserved.

If you need to roll back the app deployment, retain the additive database tables and their records. Do not drop registration tables to roll back code after participants have submitted data.

2. Publish the logo and social links

Open Admin → Website content with an account that has the content permission.

  1. Expand Site logo, upload a JPEG, PNG or WebP up to 5 MB, check Publish this content and save. A square transparent PNG with comfortable margins works well at small sizes. Uploads use the existing R2 image pipeline.
  2. Expand Social media links. Enter full HTTPS profile URLs, publish and save. Blank fields hide the corresponding icons. Links are validated against each platform's domain.
  3. Check the header, footer and /brand-icon.png. The icon is rendered as a square 512px PNG and can be cached for five minutes. Clearing the logo restores the uppercase wordmark and RH fallback icon.

For production, keep SITE_INDEXING_ENABLED=true once you are ready for public indexing. Google must be able to crawl the homepage and icon. Its search icon can take days or weeks to refresh and is not guaranteed to appear; uploading the logo cannot force an immediate Google update.

3. Open programme registration

Public address: https://remotehustle.plug99com.ng/registration. Entry points are in the navigation, footer, training page and user workspace.

  1. Check the active categories under Admin → Categories, skills & locations. The form uses the existing category list.
  2. Open Admin → Programme registrations. This requires the users permission, or super-admin access.
  3. Expand Access codes. Supply a label, optional usage limit and optional expiry date. Dates expire at the end of the selected day in Lagos time.
  4. Generate the code and copy it immediately. The app stores its hash and does not reveal the original code again. Share the copied code with intended participants. Disable a code to stop new use.
  5. Participants create or sign in to a website account, verify their email and complete the programme form. The verified account email supplies the submission's email address. Each account can submit once; retries do not consume another code use.
  6. Review submissions, mark them reviewed or reopen them, and export CSV from the admin page. New submissions also appear in the admin attention counts.

Programme registration is separate from website account approval and professional profile completion. Pending users may submit the form after verification. Inactive users cannot. Applying for jobs and purchasing resources still use the existing approval and profile gates.

The form includes all requested fields, both rules agreements and a privacy acknowledgement. Failed validation preserves the entered form values. Submitted details are visible to their owner and authorised user administrators. Corrections go through the team's contact channel; there is no self-edit screen for completed submissions.

The page displays a saved receipt. This update does not add a separate programme-registration email. Treat exported CSV files as private personal data and include them in your team's retention and deletion process.

4. Update the auth email templates

In Supabase → Authentication → Email Templates, replace the matching templates with these files:

  • supabase/templates/confirmation.html — Confirm sign up
  • supabase/templates/recovery.html — Reset password
  • supabase/templates/invitation.html — Invite user

Set the Supabase Site URL and the application's APP_URL to https://remotehustle.plug99com.ng, without a trailing slash. Add the application's callback URLs to the Supabase redirect allowlist, including:

https://remotehustle.plug99com.ng/auth/confirm?next=%2Fregistration
https://remotehustle.plug99com.ng/auth/confirm?next=%2Fworkspace
https://remotehustle.plug99com.ng/auth/confirm?next=/reset-password

Retain the existing invitation/reset callback entries required by your setup. Use your local or staging origin in its corresponding test project. The confirmation template recognises the programme destination and returns that participant to /registration; other sign-ups continue to the workspace. Test this with an email you control before sharing the registration link widely.

Application emails use the icon automatically after deployment. Supabase authentication emails use it only after you publish these updated templates. Email clients may hide images until the recipient enables them.
