Browser checks

Production build with a local Supabase fixture backend and simulated CAPTCHA UI. Chromium at 320px, 390px and 1440px; screenshots inspected internally.

  • About/contact, resource detail and purchase-link pages fit 320, 390 and 1440 pixels. CAPTCHA rendering is a local browser fixture.
  • Contact form preserves fields on server failure, permits retry, and confirms success. UI response is mocked; endpoint origin/CAPTCHA/size/storage behavior is tested separately.
  • Shared purchase link adds its product and opens the normal cart. No account, approval or profile gate bypass.
  • Admin inbox, analytics and operations fit desktop and mobile. Inbox note updates through a real server action with a mocked database. Active product editor exposes the purchase URL.
  • Sitemap includes only public active resources; robots excludes private routes; canonical and titles match products; admin is noindex. Database health returns 503 on failure, and an unknown URL returns 404.

Findings resolved

  • Contact form automatic reset removed typed values and the consent selection after a failed submission. Controlled values and reset handling now preserve the form for retry.
  • The floating customer cart covered part of the admin mobile sidebar. It is hidden on admin routes; public shopping behaviour is unchanged.
  • Malformed resource IDs are rejected before querying the database.
  • Extra margins inside the new analytics cards were removed.

Not verified in this environment

Actual company DNS/SSL, hosted migrations, production role accounts, SMTP inbox placement, live Paystack transactions, real Turnstile challenges, hosted backup execution, isolated restoration of the real database/files, Android/iOS devices, Safari/Firefox/Edge, and an external penetration test.

File antivirus/content scanning is not part of this release. The app performs type/size/signature checks and image re-encoding; agree the company's scanning solution or accepted limitation before broad uploads.
