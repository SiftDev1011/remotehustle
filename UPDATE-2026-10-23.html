Loading layouts that follow the content

The generic three-block loader has been replaced with layouts for the homepage, job listings and details, shop and product details, cart and orders, programmes, About, policies, account forms, programme registration, worker workspace and admin pages.

  • Desktop job results reserve space for both the results list and selected-job preview. The preview follows the existing mobile visibility rule.
  • Product placeholders use the same image proportions, compact grid and mobile columns as the shop cards.
  • The homepage reserves the accordion, search, featured job rows, learning and About images, and resource grid.
  • Profile, registration and job editing placeholders follow their field groups. Admin lists, content disclosures, statistics and tables have corresponding layouts.
  • Authenticated sidebars remain available when loading a destination inside the existing workspace. First entry reserves sidebar space while the layout authenticates.
  • Placeholders have a gentle opacity animation, respect reduced-motion settings, and contain no interactive controls. Screen readers receive one loading message.

Apply the update

Copy the updated src folder into your current project, keeping your own .env.local. Restart npm run dev, or deploy the updated source to Vercel. This update adds no dependencies, environment variables or database migrations.

Verification

The production build, TypeScript check and all 92 existing tests passed. Local streaming checks with delayed fixture data verified that the homepage, jobs, shop, programmes, About and cart emit their matching loading states and then their replacement content.

Browser visual verification could not be completed in this environment. Check the changes on a phone and desktop before deploying. In browser developer tools, disable the cache and select a slow network preset to make loading states easier to observe. No artificial delay is added to production.

Placeholder counts and text lengths are estimates until the data arrives. Empty results, a single product, unusually long titles and account-specific notices can still change the final height.
